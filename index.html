Model

Decides intelligence & code quality

Claude, GPT, Gemini, DeepSeek, Qwen. The model reasons over context, plans changes, and generates text, patches, and tool calls.

Harness

Decides safety, context & capabilities

Claude Code, OpenCode, Pi. The harness loads AGENTS.md, enforces allow/deny permissions, executes tools, and manages subagents.

02 · Models & Routing

Popular models: quality vs. price

Pick models by task complexity and privacy needs, not by hype. Filter the matrix below.

Family Strength Relative Cost Good For
Claude Opus Top reasoning, large refactors High Architecture, hard bugs, planning
Claude Sonnet Best quality per dollar for code Medium Daily feature work, reviews
Claude Haiku Fast and cheap Low Small edits, subagent tasks
GPT-5 family Strong general and coding; mini tiers Med – Low Broad use, cost-sensitive jobs
Gemini Pro / Flash Very large context, good value Med – Low Big codebases and docs

Prices and rankings change often. Verify on provider sites before budgeting.

Expensive

Best quality

Top Opus or GPT-5 class. Planning, architecture, tricky debugging.

Default

Best value

Sonnet, GPT-5 mid tier, Gemini Pro. Most daily coding happens here.

Bulk

Cheap & fast

Haiku, mini, Flash, DeepSeek. Search, tests, boilerplate, subagents.

Local / Self-hosted

Run on your own machine

Open-weight models (DeepSeek, Qwen, Kimi, Llama) served via Ollama, vLLM, or a private server.

  • Zero data leaves the machine
  • No per-token billing
  • Slower, less capable than top cloud models
  • Needs hardware and maintenance
Cloud / API

Provider runs the model

Claude, GPT, Gemini, and others via API or managed enterprise plans.

  • Best quality and fastest improvement
  • Pay per use; cost scales with usage
  • Code may leave your network
  • Check retention and training terms

03 · Core Concepts

Task, skill, agent, and project memory

The four building blocks that make AI agents predictable across a team.

01 · Unit of Work

Task

One bounded unit of work with a clear definition of done. Small, focused tasks succeed far more often than vague mega-prompts.

02 · Playbook

Skill (SKILL.md)

Reusable instructions: how we write database migrations, create API endpoints, or run E2E tests consistently.

03 · Isolated Context

Agent (Subagent)

Separate context window with its own role, restricted tools, and model. Example: a read-only PR reviewer.

04 · Shared Brain

AGENTS.md

Project memory: build/test commands, conventions, folder layout, and do-not rules. Read automatically at every session start.

Starter Checklist

Minimal starter setup

  1. Pick one harness and one default model for the team
  2. Add AGENTS.md to each repo: stack, commands, style rules, forbidden paths
  3. Create 2 to 3 skills for your most repeated tasks
  4. Add a read-only reviewer agent for pull requests
  5. Require branch + tests + human review for every AI change

04 · Harnesses

Popular harnesses compared

Choose one primary tool for the team to avoid config fragmentation.

Closed Source

Claude Code

Anthropic's terminal and IDE agent. Strong built-in permissions, hooks, subagents, and skills. Easiest start if your team standardizes on Claude.

Open Source · MIT

OpenCode

Terminal agent with broad provider support—including Anthropic, OpenAI, Gemini, and local Ollama models. Great for avoiding vendor lock-in.

Open Source

Pi

Minimal, extensible terminal agent built around AGENTS.md, TypeScript extensions, prompt templates, skills, and subagents.

Capability Claude Code OpenCode Pi

Model choice Mainly Claude Many providers + local Many providers + local
Permission controls Strong, built in Built in (opencode.json) Via TypeScript extensions & settings
Skills & subagents Yes (.claude/) Yes (.opencode/) Yes (.pi/)
Learning curve Low Low to medium Medium
Best for Polished Claude workflow Provider freedom Customizable minimal workflow

06 · Security & Permissions

Permission levels & deny-by-default rules

Start at Supervised Edit. Test how a deny-by-default policy evaluates real commands below.

Level 1

Read-only

Read & search code only. Ideal for PR reviews, research, and onboarding questions.

Level 2 · Default

Supervised edit

Edit files freely; prompt human to approve each shell command. Default for most work.

Level 3

Scoped auto

Edit + whitelisted commands (npm test, lint). Routine tasks in a sandbox.

Level 4

Full auto

Unrestricted execution. Disposable sandboxes only—never with real credentials.

Threat Model

Threats to know

Prompt injection
Instructions hidden in issues, docs, web pages, or dependencies can steer the agent.
Malicious plugins / MCP
Vet every tool, skill, and extension like a production dependency; pin versions.
Hallucinated packages
Verify every new dependency actually exists and is actively maintained.
Silent weakening
Agents may disable tests to pass. Protect test & CI config with code owners.
Data Protection

Secrets & data handling

  • Keep .env files, keys, and tokens out of readable paths
  • Use short-lived, scoped tokens—never production admin credentials
  • Check provider retention & training terms; prefer enterprise plans
  • Run a secret scanner (e.g. gitleaks) in pre-commit and CI
  • Restrict network egress from sandboxes to allow-listed hosts

07 · Governance & Rollout

Before we start & 4-week rollout

Guardrails, ownership, and a measured 4-week path from pilot to team default.

Policy & People

Ground rules

Acceptable use
Classify data (public, internal, confidential, regulated) and define prompt boundaries.
Approved tools
Vendor review for data residency, GDPR, retention, and contract terms.
Ownership
The developer opening the PR owns the code. AI is never the author of record.
Licensing & IP
Check dependency licenses and generated code similarity; involve legal when needed.
Process & Metrics

How we measure

Baseline metrics
Measure cycle time, review rounds, escaped defects, and effort per task first.
Low-risk pilot
Start on a repo with good test coverage, clear ownership, and no critical prod path.
Cost guardrails
Set per-user budgets, usage dashboards, and spend alerts from day one.
Opt-in culture
Share what works in a team log; review AGENTS.md during retros.
Senior Review

High-risk logic

Auth, authorization, cryptography, payments, and data-deletion flows.

Avoid Unsupervised

Critical ops

Production hotfixes, infra changes, and migrations on real data.

Early Wins

Great starting tasks

Unit tests, docs, test-backed refactors, boilerplate, code explanations.

Anti-Patterns

Watch out for

Merging unread code, weakening failing tests, or skipping PR review.
